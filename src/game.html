Read the measurements
ABYSS upgrades
Two FFT wave bands add wind detail. The hull applies a pressure head to the conservative water solver. GPU wave maps feed foam and focused underwater light. Sun shadows, impact bubbles, soft particles, and edge filtering add visible detail.
60 s verification repeats three scenes. Feature A/B uses Base, Upgrade, Upgrade, Base with equal render size. This compares switches in this build, not an old program. Cache A/B keeps physics fixed.
A short test cannot prove thermal stability or a memory leak. Percentiles describe observed samples, not free hardware capacity. All controls stay fixed during automatic tests.

  
Test integrity
The default test has six fixed time slots. Each slot includes setup, 0.5 seconds for warm-up, and the remaining sample time. Slots share one wall-clock deadline. A / B uses A–B–B–A within the same total time limit. Pending GPU queries never extend that limit.
Focus loss, a hidden tab, or a viewport change stops and marks the test. Slow visible frames remain in the data. Discarded simulation time is recorded. Settings are locked during automatic runs.
GPU samples resolve later and retain their original frame and scene IDs. Disjoint, missing, or timed-out queries are not converted to zero. Read GPU coverage before you compare results.
Capture and export wait until recording stops. Diagnostic memory sampling and numerical checks run outside timed tests. Opening a developer tool or an operating-system monitor can change performance.

  
Developer controls
Use the search field to find parameters by name. Sliders and number inputs share one registry. Pin up to ten controls. Pinned controls stay available with the main panel closed. Drag the metric and pin headers to move them.
Settings and pins use local browser storage when available. Export settings for a portable copy. Grid size and world seed require an explicit restart. Other engine settings apply live.
F2: panel. F3: metrics. F4: pins. F6: record or stop play. F7: run test. F8: pause and show diagnostics. Escape stops an automatic test. Game input does not run while you type in a field.

  
Optics / local wave update
Reflection tracing uses a conservative depth hierarchy, a separate half-size image, and depth/normal-validated history. Only current valid hits reuse history. Screen-edge and missing hits use the planar/sky fallback. No hardware ray tracing or object motion vectors are used. The underwater view captures the actual scene into six colour/depth faces and uses approximate parallax. It is not full refracted ray tracing. Local waves reflect at dry faces and use an absorbing outer strip. The large ocean spectrum is not fully reflected by this local field.
Technical references (not runtime dependencies): GPUOpen FidelityFX SSSR technique; McGuire and Mara, Efficient GPU Screen-Space Ray Tracing, JCGT 3(4); Langtangen, Finite Difference Methods for Wave Motion, Neumann boundaries.
Scope and storage
Scenes: Sluice islands, Beacon channel, Flooded arcade, and Breakwater rescue. Breakwater adds a tow line, floating cargo, depth-shaped breakers and curling surface sheets. E attaches or releases. [ and ] change tow length. The hull uses wet rectangular patches, not a closed-volume solver. Use the time slider for dawn, day, dusk, or night. Right-drag the scene to orbit; scroll to change distance. The boat checkbox hides the boat and its lamp; it does not disable hull physics. Local lights affect surfaces, particles, and bounded beam volumes. Two spotlights have opaque-geometry shadow maps. Other lamps are unshadowed. The water does not cast local-light shadows. These are real-time approximations, not full light transport.
This file has no network dependencies and sends no telemetry. It keeps at most three full reports in memory. Per-run samples and the live window are bounded. Export important reports before you close the page. Recording also uses memory. A rising heap does not prove a game memory leak.
The evidence image contains the fixed diagnostic card. It is not a screenshot of every HTML button. Use your normal screen-capture tool to include the complete interface or an external system monitor.
The console entry point is window.__tideline. Its lab, profiler, settings, parameters, game, and water fields are available. Direct console changes bypass UI validation and can invalidate comparisons.
